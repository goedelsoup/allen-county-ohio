# web

Web interface layer for this repository. Optional — add only when direct programmatic
access to the domain computer is insufficient for the intended use.

See [web conventions](../.yidam/.vendor/prelude/guidelines/directories.md#web) for what belongs here.

## Status at genesis: not applicable

There is no web interface and none is needed yet. A corpus of forty nodes is read directly,
and a browser over it would be a second way to do what `git` and an editor already do.

**What would trigger adding one.** This domain has a specific trigger that a
non-geospatial corpus would not: the corpus carries `place`, `division`, `site` and
`natural-feature` nodes whose relationships are *spatial*, and a table of edges is a poor
instrument for seeing whether they are right. The day the corpus holds enough located nodes
that a boundary error is easier to see on a map than in a diff, a map view earns its place —
and it is a corpus-correctness tool before it is a presentation one.

Two things should be settled before that day rather than after. The **data source** should
be a bundled export feed with a contract version, not the corpus read live: a page that
parses node files couples every rendering change to the ontology. And **audience** decides
the rest — an internal tool can render `[open]` claims freely, while anything public
inherits the publication rules in
[agent-conduct](../.yidam/.vendor/prelude/guidelines/agent-conduct.md), under which a
derived assertion travels only as far as the weakest claim beneath it and `[open]` does not
leave the repository at all.
