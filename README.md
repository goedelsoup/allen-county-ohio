# Allen County, Ohio

A living knowledge artifact for Allen County, Ohio — the county seated at Lima in the
northwest quarter of the state. It is organized around a single wide question: *what is
true of this county, and when was it true?* Its corpus is built to be entered from any of
three directions — a place on the ground, a moment in time, or an office and the people who
have held it — and to answer across all three rather than privileging one argument about
the county's history.

## What this is

This repository is a living knowledge artifact: its git history *is* the knowledge graph.
Files are nodes, commits are knowledge events, and links between files are edges. The
corpus in [`.yidam/corpus/`](.yidam/corpus/) is the primary knowledge store; the crates and
packages beside it are the domain computer that makes the corpus queryable.

The model this repository runs on is vendored in
[`.yidam/.vendor/prelude/`](.yidam/.vendor/prelude/) — start with
[IDENTITY.md](.yidam/.vendor/prelude/IDENTITY.md) and
[GRAPH.md](.yidam/.vendor/prelude/GRAPH.md).

## Layout

| Path | What lives there |
|---|---|
| [`.yidam/corpus/`](.yidam/corpus/) | The knowledge graph — one file per node |
| [`.yidam/catalog/`](.yidam/catalog/) | Provenance anchors: the sources the corpus draws on |
| [`.yidam/decisions/`](.yidam/decisions/) | Structured records of choices that shaped this repo |
| [`.yidam/skills/`](.yidam/skills/) | Domain skills — calculators and procedures agents invoke |
| [`.yidam/.vendor/`](.yidam/.vendor/) | Inherited yidam prelude; read-only |
| [`crates/`](crates/) | Domain computer: connectors, calculators, index |
| [`web/`](web/) | Web interface over the corpus |

`agents/`, `packages/`, and `docs/` are conventions this repository has not needed yet and
so does not have. Create each the day something goes in it, and add its row above then.

Phases run on `phase/<name>` branches and settle onto `main` with a merge commit.

## Working here

```
mise install              # provision toolchains
mise run yidam-build      # install the yidam CLI (once)
mise run regen            # refresh every REGEN block
mise run ci               # the gate CI runs
```

`mise run ci` is the whole corpus gate — `graph-check`, `graph-lint`, and `regen --check` —
and it is held to CI's by a test upstream rather than by anyone remembering to keep the two
in step. Run it, not its parts.

The yidam release this repository was vendored from is recorded in
[`.yidam.toml`](.yidam.toml). To move to a newer one, run `mise run yidam-vendor-update`.
